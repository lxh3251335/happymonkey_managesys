# 历史数据导入与核对

## 来源与选择

本轮读取用户提供的两份 Excel：对比分析表的“明细”作为归一化历史快照；原价格汇总各客户工作表用来核对该行报价和成本。文件中的说明、备注和公式只作为数据读取，不作为程序指令执行。

原始 Excel 保留不变。两份表不是两套业务流水，不能重复导入。分析表的“来源”保留到每条报价明细，包含原客户工作表与行号。

## 本轮结果

| 项目 | 结果 |
|---|---:|
| 分析明细数据行 | 855 |
| 已归属项目的历史明细 | 837 |
| 项目 | 172 |
| 其中美团小象/快乐猴 | 171 |
| 其他品牌项目 | 1 |
| 客户 | 10 |
| 单独留待复核明细 | 18 |
| 缺成本或报价的待复核项 | 13 |

172 个项目按“客户 + 原项目名称”分组，暂不自动合并名称相近的门店。原表没有明示的统一项目主键，需要用户核对后关联云智冷 ID。

18 条待复核记录包括 10 条“快乐猴项目电箱备货 / 小象项目电箱备货”、6 条“欣阳通力备货项目”及 2 条无门店归属的配件记录。它们保存在本机 `docs/import-review.json`，没有丢弃，也没有当作门店计入项目台账。

名称含“部分备货”但有具体门店的明细保留在对应项目，不能仅因为出现“备货”二字就排除。原表还包含一个京东项目，保留为“其他”品牌，避免擅自丢弃用户业务。

13 条缺失记录集中在其他品牌项目，利润保持不可计算。原始苏锦/电控箱成本与温控器、电表等成本的合计已作为历史行成本快照；不会将缺失的成本推定为 0。

## 不推断的信息

- 发货状态不等于已确认合同或应收。
- 原表没有客户回款流水，本轮不创建收款、退款或欠款记录。
- 原表未给出可靠的逐行税口径，统一标记 UNKNOWN。
- 客户名称不能自动作为供应商。原成本不自动生成为当前有效的供应商报价。
- 近似名称、相同尺寸和相近价格不证明产品配置或门店相同。

## 可复核文件与重建

原始提取结果在 `docs/source-workbooks.json`，归一化导入包在 `docs/source-seed.json`，异常与隔离行在 `docs/import-review.json`。这些文件含商业资料，和本机数据库一起被 .gitignore 排除。

提取工具仅使用 ZIP/XML 读取 Excel 的存储值与公式文本，不运行 Excel 宏或外部链接，不自行重算公式。缓存值若在源文件中已过期，应先在可信 Excel 中更新原表后重新核对。

本轮普通报价和成本数值与原价格汇总相应来源行比较，没有发现超过 0.02 元的差异。空值不会被当作“核对通过”，会单独记录。

导入是单事务，并用 import_batch 批次键保证幂等。当前批次 `source-20261114-v1`。后续修改导入规则，必须采用新的、可审查的迁移/导入计划；不要直接改批次号让全部历史数据重复入账。

后续在线导入应按“上传 → 字段映射 → 预览 → 校验/重复识别 → 人工确认 → 事务入账 → 导入结果”实施。当前只交付本轮可复现的离线导入，不提供任意格式文件上传功能。
